# CS 320 – Software Testing, Automation, and Quality Assurance

## Portfolio Reflection

### How can I ensure that my code, program, or software is functional and secure?

I learned that testing is one of the best ways to make sure software works correctly. In Project One, I used JUnit tests to check my contact service and make sure it followed the requirements. I tested things like invalid inputs, duplicate contact IDs, and updating or deleting contacts. I also learned that writing secure code means validating user input and making sure the program handles errors correctly. Testing regularly helps catch problems before they become bigger issues.

### How do I interpret user needs and incorporate them into a program?

I start by reviewing the requirements and understanding what the user needs the program to do. For example, in the contact service project, there were specific requirements for contact IDs, names, phone numbers, and addresses. I used these requirements to build the program and write tests to verify that everything worked correctly. This taught me how important it is to pay attention to the details and not make assumptions about what the user wants.

### How do I approach designing software?

When designing software, I try to break everything into smaller parts so the project is easier to manage. In Project One, I used separate classes for the contact information and the contact service. This made it easier to organize the code and test each part individually. I also learned that planning for testing early in the development process can save time and help create more reliable software. Overall, this course helped me better understand how software testing improves the quality of a program.
